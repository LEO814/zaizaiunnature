# 职责与交付契约

> 历史规划基线：本文保留初始空白项目的目录、职责与接口约定。文中的“全部待实现”“NOT_IMPLEMENTED”“未开始”等状态描述属于当时基线，不是当前 Demo 实现状态。仔仔搜打撤1.0 的实际代码能力及限制见[根 README](../README.md)与[公共主框架](../gameplay/core/README.md)，最新验收见[Demo 状态](demo_scope.json)。原生自动QA两轮各17项、手动A/D移动/UI拾取/撤离/重开（含死亡怪物复活）、默认速度/胶囊组件回读及Inspector读入70/90抽样已通过；其余参数/组合以离线校验为准。自然手动战斗、四房完整遍历及胶囊物理尺寸独立测量仍待专项验收。这不代表正式美术、多人或完整项目完成。

职责与需求修订：`0.3.0`；现有 Lua/manifest 格式：`0.2.0`。美术一个完整设定包含三专题，策划四个对象实现整包，程序四个总体系统。同一怪物的模型、移动、索敌、攻击都属于策划整包。

| 专题 | 应有设定 | 不作为交付 |
|---|---|---|
| 角色动作 | 角色形象、比例/色材、动作姿态/节奏、操作/受击/死亡状态参考 | 运行模型、骨骼绑定、动画文件、Lua |
| 怪物动作 | 外观/装饰/色材、巡逻/察觉/追逐/攻击/受击动作及效果参考 | 怪物 GLB、索敌/寻路/攻击代码 |
| 武器道具外观与 UI/UE | 外观、图标、界面布局/状态、操作反馈、场景交互物等视觉参考 | 武器道具行为、库存和界面程序 |

分别放 art/characters、art/monsters、art/visual_ui，最终统一风格/版本。说明图中动作、色材、图标和状态用途即可，不强制长篇报告。设定完成不能证明资源制作或行为完成。

## 2. 策划：模型与对应完整 Lua

策划依据美术设定完成模型、骨骼/动作、专属逻辑和基础属性挂接，再交程序合入。

| 子需求 | 同一需求聚合内容 | 程序公共接入 |
|---|---|---|
| 角色整包 | 模型/原生映射、动作、属性挂接、输入/移动、受击/死亡、持用挂点 Lua | 权威属性、底层输入/移动/动画、局次启停 |
| 怪物整包 | 模型/骨骼/动作、巡逻/移动/寻路、FOV/LOS索敌、追逐/搜索、攻击时间窗、受击特效、技能/反制、复位 Lua | 快照、底层路径/碰撞/资源、伤害提交、生成清场 |
| 武器与道具整包 | 模型/图标/动作、握持/切换及角色用动作、攻击时间窗/命中请求、使用条件/效果/消耗/取消 Lua | 物品/持用槽权威状态、原子事务、公共伤害提交 |
| 场景与交互整包 | 房间/通路/入口出口/布点、宝箱/机关/门模型动作、专属交互状态/开启/触发/联动 Lua | 公共请求权限、库存奖励事务、生成/碰撞映射、终局仲裁 |

weapons/items 同一个“武器与道具”需求；environment/interactables 同一个“场景与交互”需求。没有独立装备/护甲需求。怪物寻路策略/失败回退、索敌、攻击动作联动和受击效果不能写“待程序补齐”。

最低成品：真实运行模型/材质/动作（或已实测原生角色映射）、definition.lua、controller.lua、manifest.json、简要 README 和实际验收。当前资源全部未制作，行为全部待实现。

| 文件 | 要求 |
|---|---|
| definition.lua | 只读 ID、数值、资源/动作和规则；不存运行 HP/目标/库存 |
| controller.lua | 完整专属行为与生命周期、公共请求、失败/取消和清理 |
| manifest.json | 沿用既有字段，精确列模块/资源/clip/依赖，状态如实 |
| model/materials/animations | 真实文件；source.blend 可选，不属于最低运行资源 |
| README/tests | 引用美术依据、参数/挂接/依赖、已完成/缺口与实测 |

主模型 model/main.glb，独立动作 animations/<snake_case>.glb，贴图/图标 materials/<snake_case>.png，地图组件 model/chunks/<snake_case>.glb。clip 为 `{id, name, role, resourceId}`，指向同包运行资源。武器的角色动作 animations/player_actions.glb 不误登记到武器网格；资源格式先经 G0 实测。

## 3. 程序：总体逻辑与对象合入

| 子需求 | 必须实现 | 不移到这里的工作 |
|---|---|---|
| 比赛房间与匹配 | 创建/加入/退出、准备、匹配/开局入口、能力/失败反馈 | 专属怪物/武器控制器 |
| 赛局分配与生成 | 玩家/地图/出生点分配、生成数量/位置/时间、调用策划对象构造器、比赛音效调度、清场 | 巡逻/索敌/攻击策略、怪物专属声音触发条件 |
| 背包、仓库与商店 | 局内/局前背包、武器工具槽、仓库、商店、保存/事务及界面程序 | 道具特效、武器攻击时间线 |
| 比赛规则与结算 | 计时/死亡/超时/撤离仲裁、收益损失、结算显示、返回与重开 | 模型动作和对象技能 |

程序同时维护 core、Adapter、bootstrap/注册工具和 ui_main 共享界面。UI 按美术设定实现快照/请求/模态，归对应总体系统，不另发 UI 整包。专属行为缺陷退回策划，公共能力缺陷程序补公共层。线上匹配、同步、保存、商店能力须实测，不能用本地假状态代替。新增 API 按变更流程定义，本次不改 0.2.0 签名。

公共 Combat 仅请求合法性/攻击实例 ID、伤害治疗提交与去重；攻击时序组织属于策划。Movement/Navigation 是位移/路径/LOS 底层能力；巡逻/索敌/搜索/路线跟随与失败回退属于策划。Interaction 是请求权限/焦点；宝箱/机关状态属于策划 controller。

## 4. 生命周期与状态

现有[服务约定](service_api.md)与 core/service_api.lua 是拟议 0.2.0 外观，全部待实现。方法/request 用 snake_case，definition 数值保持 maxHp、windupSec。

controller.new 绑定唯一 instance.id，构造时不攻击/消耗。stop/dispose 清理对象路线、动作、攻击、订阅/计时器；程序启停赛局，策划对象响应并清理自己的资源。当前依赖齐全但未实现时 start 返回 `false, "NOT_IMPLEMENTED"`，未就绪返回 ADAPTER_NOT_READY，缺服务返回 MISSING_SERVICE:<name>。dispose 样板只清引用和销毁标记，不具备正式清场。公共 Result 为 `{ok, reason, request_id, data}`，不同于生命周期布尔/错误码，不得假成功。

1. HP/生命、库存/持用槽与终局只有一个权威状态；AI/技能实例状态归策划对象，UI 不改快照。
2. 策划组织按秒、覆盖跨帧的攻击窗口；公共伤害按操作/目标/tick 去重提交一次。
3. 首次索敌满足距离/FOV/LOS，失视按 last_seen_position 搜索，技能例外由策划明确。
4. 策划实现路线决策/跟随/取消/不可达回退，程序映射平台能力，不把直线移动伪装导航。
5. 物品/奖励原子提交，开始读条/失败/取消不提前扣，重复请求不重复产物。
6. 程序终局唯一结算，策划对象停用取消行为，重开不遗留目标/引用/计时器。
7. 设定、资源、行为、集成分别记录状态，不能互相替代。
