# Git 协作与项目恢复

## 仓库内容

仓库以“仔仔搜打撤1.0”的完整项目为根目录。原项目包含 232 个有效文件：225 个业务源码、文档与验收文件，以及 7 个原生场景和配置文件；本说明及后续 Git 管理文件另计。`art/`、`gameplay/`、`docs/`、`tools/`、`tests/`、`scripts/`、`dist/` 的业务目录继续遵守[目录约定](directory_contract.md)。

- `scene.data` 是当前已保存、已验收的原生场景；`project.json`、`world-config.json`、`settings/env-param-overrides.json` 和 3 个 `ai-*-generate-config.json` 保存原生项目配置。
- `scripts/modules/` 是编辑器运行包，`dist/` 是离线运行包；两者随源码一并提交，修改业务 Lua 后使用现有构建工具生成，勿手改派生内容。
- `.gitkeep` 用于保留预先约定的空目录。Git 不保存没有文件的目录。
- `.git/` 是本机 Git 数据；`.creator/`、`.demo_install_backups/` 和 Python 缓存不作为交付内容上传。`docs/editor_seed_backup/` 是安装器的种子依赖，必须保留，不属于上述临时备份。

## 克隆与恢复

1. 使用仓库提供的克隆地址执行 `git clone`，进入项目根目录，先阅读[根 README](../README.md)、[目录约定](directory_contract.md)和[公共服务接口](service_api.md)。
2. 优先使用当前编辑器支持的“打开项目”或“导入项目”入口选取这个完整项目。若当前编辑器需从本机 `projects` 目录加载，先关闭目标项目，备份已有同名项目，再将完整仓库内容放入独立的本机项目目录；保留全部场景、配置与业务文件，避免覆盖其他项目。
3. 打开后核对项目名“仔仔搜打撤1.0”、角色和方块怪物属性、脚本挂接，再进行本地运行，按 README 的验收流程检查开箱、背包、战斗、用药、撤离、结算和重开。

不要默认运行 `tools/install_editor_demo.py` 恢复仓库：它会按种子重新构建并写入场景，可能覆盖当前 `scene.data` 中已验收的编辑器状态。仅在明确需要重建场景、完成备份并理解差异时使用该工具。编辑器的跨机器导入和恢复在本次尚未实际验证，具体入口以安装版本提供的功能为准。

## 三人协作与 AI 工作约定

美术、策划、程序及其 AI agent 均先遵守根 README、各模块 README、目录与公共接口契约；稳定 ID、静态 Lua 引用、状态归属、职责边界按已有约定执行。新增接口或目录调整先记录变更理由、受影响对象及验证方式，再提交实现。

`main` 保持可运行。每项工作使用独立 `codex/<任务>` 分支，代码、资源、清单、派生运行包和验收证据一并提交，通过 Pull Request 审核合入。开始工作前拉取最新主分支，合入前确认无意外文件及对公共契约的破坏。

`scene.data` 是 ZIP 容器中的序列化场景，按二进制文件管理；同一时间由一人编辑并负责保存、验收和 PR 合入，不做逐行自动合并。出现两个场景版本时，由场景负责人选择基线，在编辑器中重新应用另一方的改动并复验。模型、贴图等二进制资源也应明确唯一编辑人，避免同时覆盖同一个源文件。
